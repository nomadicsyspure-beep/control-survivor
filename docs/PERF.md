# 성능 (렉 안 걸리는 게 1순위)

## 기준 (예산)
`node tools/perf.cjs` = 도파민 모드 후반, 몹 최대(240), 저사양 폰처럼 CPU 4배 느리게, 4초 측정.

| 항목 | 기준 | 지금 (2026-11-11) |
|---|---|---|
| FPS | 55 이상 | 54~57 (최적화 전 49.8) |
| 느린 프레임 (p95) | 28ms 이하 | 23~28ms (최적화 전 32.5ms) |
| 한 프레임 JS (update + draw) | 6ms 이하 | 약 3.5ms |

측정값은 실행마다 조금씩 흔들려서 3번 재서 본다. 기준을 넘으면 새 기능보다 성능을 먼저 고친다.

## 만들 때 지키는 규칙
1. **매 프레임 새로 만들지 않기**: `filter`·`map`으로 새 배열, 화살표 함수, `new Map` 대신 제자리 정리(`keep`), 다시 쓰는 격자. 끊김(가비지 정리)의 주범.
2. **많아지는 것엔 상한**: 몹 240, 파티클 300(가볍게 150), 스프라이트 60, 글자 40, 필살 한 타 120마리. 새 이펙트도 상한부터 정한다.
3. **많은 것끼리 비교는 격자로**: 몹끼리 밀어내기처럼 "모두 × 모두"는 칸(48)에 나눠 옆 칸끼리만.
4. **화면 밖은 안 그리기**: 몹·그림자는 화면(+여유) 안만.
5. **그리기 호출 묶기**: 같은 색은 한 번에(그림자 한 번에 칠하기). 매 프레임 그라데이션·`getComputedStyle`·글자 테두리는 아껴 쓴다.
6. **캔버스**: 불투명(`alpha: false`), 해상도 상한 1.5배(가볍게 모드 1배). 도트라 그 이상은 티가 안 난다.
7. **소리는 겹치지 않게**(throttle), 한꺼번에 많이 맞아도 소리는 몇 번만.

## 확인하는 방법
- 기능을 넣을 때마다 `node tools/perf.cjs` 결과를 PR에 적는다 (전 → 후).
- 게임 안 설정 → **성능 표시**를 켜면 왼쪽 아래에 FPS·몹 수·이펙트 수. 20ms 넘으면 빨갛게.
- 느린 폰은 설정 → **가볍게 모드** (해상도 1배, 파티클 적게).
